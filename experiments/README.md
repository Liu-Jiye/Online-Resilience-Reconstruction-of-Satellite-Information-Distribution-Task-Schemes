# 实验协议与结果管理

本目录只有规范、配置草案及空结果模板，没有新实验结果或算法运行入口。

## 完整执行方案

本轮详细方案见 [完整实验方案](complete_experimental_plan.md)，配套 [experimental_design_v1.json](configs/experimental_design_v1.json)。该方案补全环境、单跳双端资源模型、公开轨道筛选/派生窗口、6000 基实例划分、12000 主测试事件、指标公式、基线和消融。设计数字为预先约定，不是已经生成或运行的结果。旧 `extension_plan.json` 保留为上一轮草案；后续实验以 v1 为当前设计，配置变化应另立版本。

## 历史协议

`configs/original_protocol.json` 记录 S04 §5.1 明示的 50 个实例、每实例 100 候选任务、时域 5400、三种扰动及部分已报告设置。原文未给出的种子、生成器、硬件与 w 不猜测，保留 null。学习先验 PUCT 的设置来自 §5.1，不等于有可用权重或已复现完整外部方法。

主结果应区分取消主表、预算扫描、重冻结稳健性和奖励更新表。重跑时恢复各表的具体配置，不以同一配置覆盖所有实验。表 1 与表 4 的 B=2 时延存在差异，见 A07。

## 新增实验草案

`configs/extension_plan.json` 是本次提出的矩阵，`status=planned`。没有指定具体 w/时间预算/数据源的项目必须先在验证集确定，不能直接运行成最终测试。新增实验不默认沿用未知的原随机种子。

| 维度 | 计划比较 |
| --- | --- |
| 扰动 | 取消、紧急插入、奖励更新 |
| 冻结比例 | 原稿常见 0、0.6；新增 0.3、0.8 为规模分析建议 |
| 候选任务数量 | 100 为历史规模；50、200、500 为新增扩展 |
| 预算 | 0、1、2、3、5；上限需和资源/候选数一致 |
| 窗口 | 充足、紧张、无可行窗口 |
| 控制 | 固定 w/B、仅 B 自适应、仅 w 自适应、联合、验证集选参数参照 |
| 基线 | 最小修复、冻结感知贪心全局、PUCT；学习变体需恢复实现与训练 |

“不检查窗口”只用于暴露忽略约束会造成的违约，不能作为可部署可行方法排名。所有方法的输出都由同一完整检查器统计窗口违规。网格参数用验证集选择；如报告每测试实例全知网格最优，只能标作离线参照，不算在线可用算法。

## 指标与统计

- 保存原始总效用、删除/新增数量、保留项移动秒数、原始分母，再派生原论文指标；原指标未恢复前不混用。
- 严格可行率：完整硬约束通过数 / 全部实例数；严格紧急成功率额外要求紧急任务已排入。
- 单列冻结违规数、窗口违规数、窗口拒绝候选数、无解未找到、超时、证明不可行与未知。
- 使用同实例配对比较，报告均值与 95% 区间、成功数/总数。成功子集的效用必须列出分母，并同时给全实例结果和失败处理规则。
- 实例级区间可用预先确定的配对 bootstrap，重复计时应与跨实例不确定性分开；该做法是新建议，不声称原论文采用此计算法。
- 计时覆盖状态提取、候选筛选、参数控制、修复及最终校验；报告控制开销、硬件、预热、重复次数。不要解释为真实星间系统端到端时延。

`results_template.csv` 只有表头。运行结果建议写入 `runs/<experiment_id>/`，保存 config、environment、instances、per_instance_results、summary 和失败记录，再按需要发布固定版本。
