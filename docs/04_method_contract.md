# 方法接口与约束草案

本页供后续实现使用。冻结前缀、局部编辑、插入预算和词典序来自 S03/S04；传输窗口与参数控制来自 S02/S05。下列单位、接口与失败状态是本仓库建议的新规范，尚非原实现事实。

## 输入与输出

输入包括任务集合、参考计划 P、首个可编辑位置 k、扰动描述、邻域宽度 w、预算 B、总响应时限、资源与窗口。论文用 1 起始位置；建议代码使用 `frozen_count=k-1`，避免 k 与零起始索引混淆。

计划项至少包含任务 ID、开始/结束时刻和占用资源。输出含修复计划、状态、拒绝原因、指标、选定 w/B、参数控制时延与总时延。状态建议为 `feasible`、`no_feasible_repair_found`、`timeout`、`frozen_conflict`。`no_feasible_repair_found` 不等于数学上不可行。

## 不可放宽的约束

1. 冻结前缀任务 ID、顺序、开始/结束时间和资源逐项保持。冻结项被取消或接触窗口失效时，报告冻结冲突，交由上层解除承诺，不能静默删除。
2. 任务唯一；取消的未冻结任务不能保留；任务窗口、时序、机动和资源限制均需检查。
3. 明确可编辑邻域的边界与单位。S04 式 (7) 为 `k <= i <= min(m,b(d)+w-1)`，并非自动等同对称中心邻域；采用哪一种须在正文、配置与实现中一致。
4. 预算 B 为非负整数；每次接纳的新增任务必须记账，包括替换时新接纳的任务。紧急任务是否计入预算应在恢复原实现后固定，不得各方法自行处理。
5. 候选的局部检查通过后仍须检查整个计划，尤其是冻结/编辑边界和邻域外任务的资源冲突。

## 星间传输扩展

第一阶段建议只支持单跳、固定速率、单窗口完成；多跳、分片、带宽共享和缓存因果约束另行扩展，不能默认已经支持。

对发送卫星 s、接收卫星 r、数据量 D（bit）、速率 R（bit/s），要求 `s != r`、`D > 0`、`R > 0`，传输时长 `duration = D/R`（s）。需要某一有效接触窗口 `[a,b]` 和开始时刻 t，使 `a <= t` 且 `t + duration <= b`，同时完整落入任务自身执行窗口。

窗口绑定卫星对及方向，链路是否双向应由数据声明。发送方和接收方在整个传输期间都必须有资源，接触窗口内存在空隙并不代表两个端点同时可用。建议资源占用用半开区间 `[start,end)`，允许一项结束时下一项恰好开始；数值容差在配置中明确。若存在建链/切换开销，计入占用时长。首版不允许跨多个窗口累计传输。

必须覆盖：恰好结束于窗口右边界；短于传输时长的窗口；无窗口；反向卫星对；接收冲突；冻结边界冲突；非法速率；重复任务；候选跨两个短窗口但单窗口均不可行。

## 候选裁决与记账

先拒绝硬约束不满足的候选，再按效用最大、任务集合干扰最小、插入负担最小、保留任务时间移动最小逐项比较；并列时用确定性规则。效用相等的容差必须记录。不得用加权和悄悄替换词典序。

原“集合改动”与新增任务负担应分离恢复定义。新接口同时记录 `removed_count`、`added_count`、`retained_count`、`retained_movement_s` 等原始量，再派生归一化指标，明确分母。不可把“零集合改动”理解成没有新增任务。

## w/B 控制器

可用状态：当前已观测扰动强度、冻结比例、局部可行候选数、剩余响应时间。初始 `w0` 必须由配置给出，B=2 仅是原协议的有依据默认值。

控制动作受 `w_min/w_max`、`B_max`、可行候选数与资源限制约束。局部可行候选数也依赖 w，因此先用当前邻域统计，再迭代扩大；每轮筛选与控制开销计入总时限。冻结比例高、余量小则保守；强扰动且可行候选充分时才扩大。具体阈值需预先在验证集确定。

规则控制器是启发式；若要提出学习算法，应补状态/动作/奖励、训练数据、验证方法及成本。超时返回已验证的最佳可行候选；若没有，显式失败。不能通过返回扰动前但已失效的计划冒充成功。
