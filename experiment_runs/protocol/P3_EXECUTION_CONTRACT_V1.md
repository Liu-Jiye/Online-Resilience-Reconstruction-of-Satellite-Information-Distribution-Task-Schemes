# P3 执行补充契约 v1

本补充不改动既有冻结文件。仅执行 P3；依据 P3_APPROVED_SCOPE_V1.md 及用户全部确认。任何验证表现产生前冻结本契约和 configs/p3_v1.json。

数据分配、两层配对、全部 12 情景及 80000 条上限均按已确认范围。实例种子依 D1、D2-S、D2-O 顺序从训练 190000、验证 290000 连续分配；训练到193999、验证到290999。P3 命名空间独立于早期压力组。事件种子为 SeedSequence([instance_seed,93001,scenario_index]) 的首个 uint64。配对层共享种子，不共享参考计划，紧急任务的效用按各自需求中位数生成。每训练实例情景取其全局序号模12，近似均衡且不看结果；同一实例全部动作不拆分。轨道组按层内序号轮转，严格限制在相应划分的6/2组。任何生成失败记录后停止，不基于方法表现补样。

参考规划用已核验的 indexed_reference，逐实例与独立整数位集贪心完全一致并校验。5000 场景仅作5000个基实例；另有5000配对负载变体。测试组不生成、不求解。保留快照来源、分组、输入、事件、源码、镜像与全部派生文件哈希。

固定网格30动作；规则候选限定 JSON 中三组，完整验证仅选择一轮，不追加候选。每层数据按三数据层×12情景等权宏平均：在线成功优先，其次执行效用除以事件后原参考任务效用总和（分母下限1），再比较删除、新增、全体移动、总体p95及预设配置顺序。失败和超时不剔除；非适用取消事件单列，非适用不计成功率分母。默认与中竞争分别冻结，不读测试结果。

规则/ET特征、候选判断、推理、修复、最终校验全部计入50ms。模型加载、文件读取与离线参考计划不计入，但单独记录。特征处理超时不能获得重新50ms。紧急机会以空可编辑后缀、保留冻结/日历的可行放置定义，只用于B至少1，不能推断局部修复一定成功。无单独可插入候选时B0仍保留该紧急机会覆盖。ET成功标签为既适用、物理及冻结/预算等校验通过、紧急服务通过且按时的 online_success；数值标签保留原始效用变化、删除、新增、移动、总时延，失败情况不伪填成功。训练统计量仅来自训练，所有验证校准单独登记。

搜索配置严格沿用方案6.2；温度只从三值按同一宏平均规则选择，验证种子11，余四种子保留后续阶段，不声称已执行。ALNS使用包框架和本任务算子，PUCT为密度先验适配实现，均不称论文原代码复现。搜索改进只在可行、冻结与累计接纳预算合规时接受。

正式环境为固定Python3.11/Linux容器，单CPU亲和性且数学库线程1。Debian Bookworm及实际Docker VM内存与方案建议Ubuntu22.04/32GB有差异，报告实际配置；不拿Windows计时选参。安装成功、依赖lock、Linux回归及镜像ID全部记录后，方可运行正式方法。旧环境失败记录保留，恢复记录另存。
