## 模型和输入

任务、窗口、日历、计划、事件、案例由不可变 dataclass 表达；正式交换采用 JSON，重载时重新执行输入检查。任务数据量与速率为正整数 bit、bit/s，效用为非负整数；本协议预设的数据量/速率均可精确表达。重复 ID、非法端点、非法速率、超时域输入直接拒绝。

占用时长使用 `1+(D+R-1)//R`，精确等于 `ceil(1+D/R)`。物理窗口按 `(ceil(a),floor(b))` 内缩；取整后空窗口删除。任务自身时间窗必须由调用方提供整数秒。终端占用为 `[start,end)`，恰好结束于窗口右端或与另一项首尾相接合法。两个相邻但各自过短的独立接触窗口不自动合并为一个可用窗口。

每卫星一个半双工终端；发送/接收角色共用资源。任务双方均检查接触、资源、外生日历；可同时安排资源不相交的任务。P0 提供 60 s 槽的 PCG64 日历构造工具，合并连续忙槽并记录实际忙比例，仅在单元测试使用，未开展 P1 数据生成。

`Case.base` 是扰动前实例，`reference` 必须是该实例的可行且按 `(start,id)` 排序的计划；`frozen_count=floor(FR×|P|)`。`post_event_contacts` 可选字段只用于正确性边界输入，表示外生窗口变化后的完整窗口表；本次不运行窗口扰动研究。原计划先对 base 核验，再对事件后的窗口做冻结冲突判断，避免把外生失效误判为原参考计划错误。

## 参考计划与事件

参考规划按精确有理数效用密度降序、deadline 升序、ID 升序，每项寻找最早可行位置，每次插入独立校验。初始构建时长另记，不混入在线修复；排入数、终端占用秒数和扣除忙日历后的空闲段随计划保存。

事件使用独立 `Generator(PCG64(event_seed))`，输入 ID 先排序。取消只抽未冻结已排项，数量 `min(m,max(1,ceil(q*m)))`；m=0 保留 N/A，不重采样。奖励更新从未冻结的已排及未排任务抽 `ceil(0.3*n)` 项，乘 `1±q` 后采用精确有理数的 ties-to-even 四舍五入，最小 1。30% 数量向上取整是公开的确定性细化。紧急请求 80% 从有接触方向对、20% 从全部不同端点对抽样；不保证当前时刻 0 后有可用窗口。释放为 0，q=.2/.8 对应 deadline600/120，D/R 按原分布抽样；效用为基任务效用中位数的 5 倍，若为半整数再 ties-to-even 到整数。主算法不得修改共享输入。

## 邻域与候选

用户于 2026-11-05 确认：多取消取受影响原计划索引的下中位数；奖励变化先取已排变化项索引的下中位数，若全未排则由其可行开始区间中点映射；无可行窗口回退首个可编辑位置。

具体映射：每个任务窗口与有方向接触窗口相交后得到合法开始区间 `[left,right-p]`，对这些区间各取中点；多区间/多任务取中点的下中位数。映射到开始时刻不早于该中点的首个原计划位置，超尾裁剪到末项；再裁剪到首个可编辑位置。尚无后缀时编辑集合为空。

E 严格由原计划索引 `i>=frozen_count 且 |i-center|<=w` 定义；不随编辑扩大。候选任务自身窗口需与 E 时间跨度或取消释放时段相交；空后缀紧急项用自身可行窗口定义时间范围。保留项中 E 外的字段必须保持；原计划内可再次接纳的任务也限制在 E 内。放置仍按任务完整窗口、接触窗口与双方空闲段求最早可行时刻，候选资格的时间相交不代替资源检查。

多取消只影响中心下中位数，所有外生取消均必须删除、释放时段均进入候选资格；不将各取消中心邻域取并集。候选与移除对象均按 ID 遍历，严格质量并列时保留首个，避免不必要编辑。

## 算法、预算和独立审计

- 共同基准：冻结冲突返回 `frozen_conflict`；删除取消项；逐项保留仍合法的未冻结承诺，否则记录强制删除及原因，不算算法主动干扰。
- Minimal-Repair：仅上述必要修改；紧急项在预算非零时尝试一次最早可行插入，不主动替换。
- Fixed-PALR：默认 w=5/B=2；保留当前方案，枚举 E 中单项替换，再枚举直接插入；每轮选严格改善词典序的最好候选，接受后完整校验，直到无改善、累计预算耗尽或截止。没有未声明的多项替换、移位或全局重排。
- Frozen-Greedy：冻结不动，从其余未取消任务重建后缀；紧急项首先尝试，其余按 u/p、deadline、ID。每个可行构建前缀作为候选，与最近已验证 incumbent 比较，仅保存严格改善者，因此可退回共同基准，不以较差重建覆盖更好的已验证结果。新接纳上限默认 5。
- 服务裁决：紧急成功优先，再比较 `(-U,N_drop,N_add,M_all)`；其他扰动直接用这四元组。合法但未接纳紧急任务是计划可行、服务失败，不称已证明不可行。
- B 限制相对原参考计划的累计新接纳操作数，含紧急与替换新增项。候选枚举不算接纳；只有接受为 incumbent 的状态变化写入账本。反复移除和接纳同一新项每次重新计数，最终新增数另算。B=0 不接纳紧急项；固定 PALR 此时直接保持基准。
- 独立校验器不引用搜索/放置/参考规划代码；同时复算时长、完整窗口、双方资源、日历、冻结、取消、E 外保持和累计预算。预算审计必须有初始状态与操作轨迹；逐步重放并独立核验每个接受状态，不能只检查最终新增数。

初始候选统计记录时点为“已验证基准、固定 E、修复开始前”。纯窗口拒绝与基准资源拒绝分别按唯一 ID 计数；`n_feas_initial` 是单独可插入数，不代表同时可插入。只对固定 PALR 做该统计；基线标 null。若截止中断统计，`candidate_census_complete=false` 且 n_feas 为 null。

## 计时、指标和证据

`perf_counter_ns` 起于在线输入核验/事件应用前，截止于最终完整计划校验之后；包含事件副本、基准构建、候选/状态提取、搜索、接纳审计、最终审计。一次性文件读取、参考计划构建、事后统计和 JSON 写盘单列于在线区间之外。固定方法控制时延为 0；分项为输入/基准、筛选、修复、接纳校验、最终校验和未归属开销，总和严格等于实测总时长。

合作式截止在候选循环、资源扫描、接受前后检查；不可抢占的一次校验可能越界。验证结束已超时的候选不接纳；最终检查导致超时的方案可保留合法性审计，但 `U_exec=0`、在线成功为 false。没有已验证 incumbent 的超时输出不计可行成功。P0 不宣称硬实时。

指标按完整方案 §5：取消与外生强制删除从主动删除分母剔除；新增仍以原参考集合为准；全保留/可编辑保留的移动分开；奖励统一用事件后值；非法方案只保留诊断 U_raw，合法 U 可单列，超时或无有效输出 U_exec=0。N/A、计划可行、服务成功、按时成功分别记录；汇总保留全部适用事件分母和条件均值分母。与 Minimal-Repair 的增益由同事件结果配对计算。

P0 的人工微型输入、单元测试和错误注入不是研究数据，不能用于支持算法优越性。P1 轨道/生成器、P2 CP-SAT、P3 参数验证/控制器、P4 主测试及 P5/P6 全部等待用户分阶段指示。

## 复跑

在仓库根目录建立本目录内的独立虚拟环境，安装 [已验证依赖锁](../environment/requirements-p0.lock.txt)。当前实际验证平台为 Windows/Python 3.14，目标 Linux/Python 3.11 尚未验证，不将本机时延用于主评测排名。

```powershell
python -m venv experiment_runs/.venv
experiment_runs/.venv/Scripts/python.exe -m pip install -r experiment_runs/environment/requirements-p0.lock.txt
experiment_runs/.venv/Scripts/python.exe experiment_runs/scripts/run_p0.py
```

运行器只执行 P0，输出独立 `reports/p0/P0-<UTC>/`，保存 pytest 文本/XML、人工实例、参考计划、12 个事件、36 次方法调用、参数、轨迹、完整计划、指标、环境、源码哈希与产物哈希。目录已存在时拒绝覆盖。Linux 复跑需使用相应虚拟环境解释器路径并重新验证可用依赖；平台专用包不构成跨平台兼容性承诺。

单例复跑可用 `scripts/run_case.py --case <cases.json> --index 0 --method Fixed-PALR --output <experiment_runs内新文件>`，可指定 `--w`、`--B`、`--budget-ms`；它不会启动后续实验阶段。
